## Goal (Birk, 2026-10-18)

In Wing's voice settings, the user must be able to manually choose the
microphone, not only rely on automatic BT/wired/phone detection.

## Required behaviour

- New setting "Microphone": **Automatic** (default) | **Phone mic** |
  **Bluetooth device** | **Wired headset**.
- "Automatic" = the existing rule from HeadsetMicRoute.kt /
  android/.../voiceoffline/HeadsetMicRoute.kt `decide()`: a connected BT
  device with a mic is used, else wired headset, else phone.
- A manual choice applies to ALL recording paths that currently call
  HeadsetMicRoute (dictation/local recognizer, vad explicit rounds, auto
  mode / conversation loop). Do not build a second routing path — hook into
  the SAME routing call site that the existing BT chain (t_1a2b5df1 /
  t_4450aa3b) already uses: `HeadsetMicRoute.decide()` /
  `HeadsetMicRoute.acquire()` in
  android/app/src/main/kotlin/com/tarkilhk/wing/voiceoffline/HeadsetMicRoute.kt,
  called from VadCapture.kt and VoiceChannel.kt (see commits 4be9e89d,
  76843d74 on this branch for the existing call sites).
- If the chosen device is not currently connected, Wing falls back to
  "Automatic" and shows this once, briefly (e.g. a short snackbar/toast via
  the existing Studio error/snackbar helper — look at
  lib/core/widgets/studio_error.dart for the existing pattern used by other
  voice settings rows). No silent failure.
- Optional, only if cheap: list the actually available input devices
  (AudioManager.getDevices(GET_DEVICES_INPUTS)) with names (e.g. "WH-1000XM4",
  "Phone") — skip this if it needs new plumbing beyond what already exists;
  the four fixed choices (Automatic/Phone/Bluetooth/Wired) satisfy the
  acceptance criterion on their own.

## Where this plugs in (read before coding)

- Dart side: lib/core/services/voice_preferences.dart holds all
  VoicePreferences keys/choices/parsing (see e.g. vadSourceKey as a precedent

  (e.g. `micRouteKey` with values `auto`/`phone`/`bluetooth`/`wired`) alongside

- UI: lib/core/widgets/voice_preferences_card.dart is the voice settings
  screen ("Saved on this phone" section with the existing `StudioSelect`
  rows, e.g. the "Voice input" StudioSelect at the file's build() method).
  Add a new StudioSelect row for "Microphone" near the other input-related
  settings, following the same `StudioSelect<String>` + `onChanged` +
  `_save(...)` pattern as the existing "Voice input" row.
- Native/Android side: HeadsetMicRoute.kt's `decide()` currently always
  computes automatic BT-vs-phone. Give it a way to receive the manual
  preference (plumbed from Dart through the existing MethodChannel used by
  VoiceChannel.kt / VadCapture.kt — read those two files to see how
  HeadsetMicRoute is already wired up) and respect it:
  - `phone` → always `Decision(false, "manualPhone", null)`, i.e. never
    attempts the BT SCO link regardless of what's connected.
  - `bluetooth` → use the existing BT branch of `decide()`; if no BT headset
    mic is currently available, fall back to automatic behaviour and signal
    the fallback up to Dart (so the UI can show the one-time hint).
  - `wired` → same idea for the wired-headset case; HeadsetMicRoute today
    only handles the classic-SCO/BT link path (see its header comment: "the
    default engine routes wired, USB and LE Audio mics by itself"), so
    "wired" may mean: skip the BT link entirely (`Decision(false, ...,
    null)`), which lets Android's default engine take the wired mic as it
    already does. Confirm this against the existing `decide()` logic and
    adjust the reason string so logs stay informative; do not add a second,
    parallel implementation of the wired/USB detection — if it's not needed,
    say so in your summary.
  - `auto` → exactly today's unchanged behaviour.
